1) Команда ps (https://losst.ru/komanda-ps-v-linux)

Утилита ps для просмотра списка процессов в Linux

ps опции

Примеры:

ps -d   выбрать все процесс, включая фоновые и лидеры групп:

ps -p 943  выбрать процесс по Pid = 943

ps -fp 943  выбрать процесс по Pid = 943 с выводом доступной информации

ps -Fp 943  выбрать процесс по Pid = 943 с выводом максимум доступной информации

ps -mFp 943  выбрать процесс по Pid = 943 с выводом максимум доступной информации и отображением потоков ниже процесса

ps -mFC dotnet  выбрать процесс по имени dotnet (команда -С) с выводом максимум доступной информации и отображением потоков ниже процесса

ps aux | grep dotnet  вывести информацию о процессе dotnet

ps aux | awk '{print $2}' вывести содержимое второго столбца (Pid)

11.2) Утилита dpkg и grep

dpkg -l | grep -i "gnivc\|ao" 

что делает: фильтрует строки из вывода dpkg -l, оставляя только те, в которых встречается gnivc или ao.

    dpkg — базовый пакетный менеджер для Debian и его производных. Управляет пакетами формата .deb.
        -l (или --list) — опция, которая выводит список всех установленных в системе пакетов.
    | - Оператор конвейера (pipe) в Bash. передаёт вывод предыдущей команды (dpkg -l) 
        в качестве входных данных для следующей команды (grep).
    grep — утилита для поиска строк, содержащих заданный шаблон.
        -i — опция, игнорирующая регистр букв (ищет GNIVC, gnivc, Ao, ao и т. п. одинаково).
        “gnivc|ao” — шаблон поиска:
            gnivc — первая часть условия (искать пакеты с gnivc в имени);
            \| — экранированная вертикальная черта, обозначающая логическое «ИЛИ» в регулярном выражении;
            ao — вторая часть условия (искать пакеты с ao в имени).

13) Получит список всех зависимых пакетов

apt-cache depends wireshark | grep -v "Depends: <"

где
	apt-cache depends wireshark - выводит полный список зависимостей пакета wireshark
	Типы зависимостей в выводе:
    		Depends: — обязательные зависимости (без них пакет не установится);
    		PreDepends: — зависимости, которые должны быть удовлетворены до установки пакета;
    		Recommends: — рекомендуемые пакеты (устанавливаются по умолчанию, но не обязательны);
    		Suggests: — пакеты, которые могут расширить функциональность;
    		Conflicts: — пакеты, с которыми данный пакет конфликтует;
    		Breaks: — пакеты, работа которых нарушается при установке данного пакета;
    		Replaces: — пакеты, которые будут заменены при установке;
    		Provides: — виртуальные пакеты, которые предоставляет данный пакет.
    		
	grep -v "Depends: <" - фильтрует вывод первой команды, убирая ненужные строки.
		-v (или --invert-match) — флаг, который исключает строки, соответствующие шаблону (выводит всё, кроме совпадений);
		
14) Обновить пакеты
Чтобы обновить пакет bash в Ubuntu, нужно выполнить несколько шагов. Обновление пакетов в Ubuntu осуществляется через систему управления пакетами APT.

14.1) Обновить список доступных пакетов из репозиториев.
sudo apt update

Эта команда синхронизирует локальный кэш пакетов с удалёнными репозиториями, чтобы система знала о доступных обновлениях.

14.2) Обновление конкретного пакета в том числе и bash
sudo apt install --only-upgrade имя_пакета

--only-upgrade гарантирует, что пакет будет обновлён только в случае, если он уже установлен. 
		Если пакет не установлен, команда не выполнит никаких действий.
		
14.3) Обновить все пакеты, которые имеют доступные обновления.
sudo apt upgrade

Эта команда обновит все установленные пакеты до их последних доступных версий. 

14.4) Обновление, которое может устанавливать новые зависимости или удалять ненужные пакеты
sudo apt full-upgrade

15) Удаление пакета

15.1) Удаляет пакет, но оставляет конфигурационные файлы
sudo apt remove имя_пакета

Используйте, если хотите удалить программу, но сохранить настройки на случай переустановки.

15.2) Полностью удаляет пакет и все его конфигурационные файлы
sudo apt purge имя_пакета

Подходит для полного удаления без остатков.

15.3) Удаляет пакеты‑зависимости, которые больше не нужны
sudo apt autoremove

Запускайте после удаления программ, чтобы убрать «мёртвые» зависимости.

15.4) Удаляет зависимости и их конфигурационные файлы:
apt --purge autoremove

15.5) Очищает локальный кэш скачанных пакетов (удаляет .deb‑файлы из /var/cache/apt/archives/):
sudo apt clean

15.6) Более щадящая очистка кэша: удаляет только устаревшие пакеты

sudo apt autoclean

17) Команда перехода cd

17.1) Переход в родительскую директорию относительно расположения самого скрипта

cd "$(dirname "$0")/.." || exit 1

  $0 - Содержит имя (и путь) исполняемого скрипта — то, как он был вызван в командной строке.

    	Примеры:
    
	1) Если запустить скрипт как ./myscript.sh, то $0 будет ./myscript.sh.
	2) Если вызвать его как /home/user/scripts/myscript.sh, то $0 примет значение /home/user/scripts/myscript.sh.

  dirname "$0" - Команда dirname извлекает из пути к файлу часть, относящуюся к каталогу (директории), убирая имя самого файла.

    	Примеры работы:

	1) dirname "./myscript.sh" → . (текущая директория).
	2) dirname "/home/user/scripts/myscript.sh" → /home/user/scripts.

  $(dirname "$0") - Синтаксис $() выполняет команду внутри скобок и подставляет её результат в строку.
	           В данном случае он подставляет путь к директории, где находится скрипт.

  $(dirname "$0")/..  - К полученному пути добавляется /.. 
                        Символ .. означает «родительская директория» — каталог на уровень выше.

    	Примеры результата:

	1) Если скрипт в ./myscript.sh (текущей директории), то $(dirname "$0")/.. → ./.. (родительская директория текущей).
	2) Если скрипт в /home/user/scripts/myscript.sh, то $(dirname "$0")/.. → /home/user/scripts/.. → /home/user (родительская директория scripts).

   cd "$(dirname "$0")/.." - Команда cd (change directory) выполняет переход в директорию, указанную в результате подстановки.
                             Кавычки " вокруг выражения нужны для корректной обработки путей, содержащих пробелы или специальные символы.

   || exit 1  - Оператор || выполняет следующую команду (exit 1), только если предыдущая (cd ...) завершилась с ошибкой (возвратила ненулевой код выхода).
                exit 1 завершает выполнение скрипта с кодом ошибки 1. Это сигнализирует, что произошла проблема (в данном случае — не удалось перейти в нужную директорию).
                
18) Условная конструкция if‑else

if [ $? -eq 0 ]; then
    # действия при успехе
else
    # действия при ошибке
fi

Логика: если код возврата предыдущей команды равен 0, выполняются действия в блоке then. Иначе — в блоке else.

if ... then ... else ... fi — синтаксис условного оператора Bash.

$? — специальная переменная Bash, хранящая код возврата последней выполненной команды.

-eq — оператор сравнения «равно» (от equal) в контексте теста [ ].

[ ... ] — команда test, оценивающая выражение внутри скобок. Возвращает 0 (истина) или 1 (ложь).

0 — стандартный код успешного завершения любой команды в Unix‑подобных системах.
